# FPLVORTEX v0.4 — Forward-only GW1–GW6 research protocol

## Reality check, 17 October 2026

- The [official Premier League fixture calendar](https://www.premierleague.com/en/matches/premier-league/2026-27/matchweek-6) shows GW6 completed 10–12 October. GW7 runs 17–19 October.
- We **do not** have licensed event/lineup data or independently archived pre-kickoff GW1–GW6 projections in this project. No verified model-accuracy percentage is presently calculable.
- The [official FPL Terms](https://fantasy.premierleague.com/help/terms) prohibit automated extraction and commercial use without permission. Do not scrape the unofficial public endpoints as a workaround.

## Honest evaluation process

1. Obtain a legitimate license from an appropriate data supplier for fixture histories, player lineups, appearances, xG/xA, injury and availability, and headshots separately.
2. Make source timestamps immutable and append-only; retain exact source content hashes and data-rights declarations.
3. For each test GW 1, 2, 3, 4, 5, 6, generate a prediction using **only** features available before its deadline. Early GWs can use licensed previous-season training history; GW1 cannot train on any GW1 result. If no archive is available, label backtests as *retrospective replay*, not genuine historical forecasts.
4. Freeze the forecast payload and its prediction timestamp before loading actual outcomes for that GW. No cross-GW leakage through rolling means, global scalers or injury notes published after kickoff.
5. Import officially finalized score and appearance results. Evaluate **MAE** and **RMSE** in points, mean bias, starting XI Brier score, xG/xA calibration/Poisson deviance, and clean-sheet log loss. Report sample size and missing-row coverage per GW.
6. A bounded performance indicator can be **within ±2 points** = count(|forecast-actual|<=2) / all rows. It is NOT an unqualified accuracy percentage and doesn't establish superiority to any commercial model.
7. Benchmark against simple, genuinely historical baselines (position average, six-match exponentially weighted mean) and against a licensed third-party forecast only when provider terms allow it. Show confidence intervals/bootstraps before claiming improvement.
8. Do not tune hyperparameters on GW6 and then report GW6 as a held-out test. Use nested rolling validation, freeze candidate models, then evaluate new future GW7+ results prospectively.

## Current implementation and remaining gates

- Backend supports validated/rights-attested snapshots, historical PG batch imports and MAE, RMSE, bias, start Brier and calibration bins.
- `/api/v1/research/gw-validation` returns separate GW1–GW6 metrics where a legitimate archive has been imported; otherwise explicitly returns an empty, pending result.
- `/api/v1/data/appearances` returns starts, substitute appearances, subbed-off counts, observed fixture counts and average minutes if an approved local appearance export has been configured.
- An independent empirical-Bayes research prototype calculates predicted starts, xMins, xG, xA, CS% and xPts from a player’s input priors and available history. Its priors currently use **synthetic demo values**, not verified live 2026/27 priors.
- Deep Solver: 10-week bounded beam search, price/club/formation rules, captaincy, rollovers, Free Hit reverting squads, first-half chip scenarios. It tests only limited candidate WC/FH transfers; no claim of global optimization or correct chip preference without calibrated inputs. It does **not** implement a complete bench autosub or actual selling-price model.
- Price movement: will not invent ETA from unknown league thresholds; an authorized price/transfer time series and out-of-sample calibration are necessary.
- Five Commons-sourced player photos are documented in `docs/photo-credits.md`. Other portraits fall back to initials until a suitable license is available.

## Automated checks

`npm test` runs the deterministic algorithm/unit, HTTP, SQL-integration (CI), source-status and appearance tests; GitHub Actions supplies PostgreSQL. This is not a schedule of continuously updating licensed FPL data. Browser visual navigation in the current execution environment was blocked by policy and remains pending.
