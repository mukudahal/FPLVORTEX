## Decisions to resolve before dependent phases

- The fixed weighting is currently an assumption (0.85 in several paths), not a demonstrated backtested optimum. Read the approved value from versioned configuration later; do not silently choose a new value during Phase 1.
- Simulation budgets must be reconciled explicitly: requested 3,000 baseline versus 10,000+ detailed evaluation. Actual counts must always be reported, with unsupported Deep capabilities disabled.
- The supplied statement that opposing clean sheets cannot both occur conflicts with a 0–0 result. Both sides have a clean sheet in that outcome. Propose that mathematical correction before building the full scoreline evaluator; do not silently edit the attached text.
- The illustrative two-FT example and single-use chip equations are not the stated 2026/27 format. Active official-rules configuration must govern future implementation, with explicit chip windows/counts and configurable FT cap.
- Bench Boost must replace ordinary bench autosub contribution with full eligible bench scoring, not add it twice. Any linear approximation must be labelled and must not be presented as the validated full evaluator.
- Source-specific freshness thresholds need an approved policy, especially lineup/odds/injury sensitivity near a deadline. Existing polling intervals are not an approved freshness policy.
- User-supplied values can support an explicitly confirmed scenario; they must never be upgraded to official verified account state. No passwords or unofficial credential collection.
